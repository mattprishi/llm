# HW5 · RL для вызова инструментов

Обучаем LoRA на `Qwen/Qwen3.5-2B@15852e8c16360a2fea060d615a32b45270f8a8fc` через TRL. Источник обучения — только `Team-ACE/ToolACE@6bda777c88d21e5a204703c1ee45597a8fa4f734`. Seed — 42. Исходные Dockerfile, BFCL и оценщик сохранены.

| Конфиг | Награда | Loss |
|---|---|---|
| `rl1` | Строгая | GRPO: усреднение по ответам |
| `rl2` | Частичная | GRPO: усреднение по ответам |
| `rl3` | Частичная | `dapo`: усреднение по токенам |

Во всех трёх случаях одинаковы нормировка advantage, clipping, модель, адаптер, данные, seed и бюджет. В `rl3` сравниваем только знаменатель loss. Чекпоинт выбирается по строгой метрике на 36 фиксированных примерах из 128 отложенных ToolACE (по 12 на один вызов, несколько вызовов и no-call). BFCL используется для итоговой оценки.

## Воспроизведение

Из этой папки. `device=1` — пример для выделенного устройства; используйте назначенный индекс или UUID.

```bash
docker build -t rlvr-homework .
docker run --rm -it --gpus device=1 --ipc=host \
  -v "$PWD":/workspace -v rlvr-hf-cache:/cache rlvr-homework
bash run_stage.sh preflight
bash run_stage.sh data
bash run_stage.sh base
bash run_stage.sh pilot 6 256
# После пилота задайте единый бюджет и интервал validation для трёх запусков.
for run in rl1 rl2 rl3; do
  bash run_stage.sh "$run" 40 20 256 || break
done
python3 audit_results.py --require-complete
```

Обучение и экспорт можно запускать и напрямую в отдельном Python-окружении. `train_rl.py --help` показывает параметры. BFCL для всех четырёх моделей должен запускаться в одном окружении. Код, ожидаемые артефакты:

- `prepare_data.py` → `data/{train,val,examples}.jsonl`, `data/eda.json`.
- `verify_toolace.py` → проверка сплита, точного рендера Qwen и награды на всех эталонах.
- `rewards.py` → строгий и частичный баллы; `python3 -m unittest test_reward` проверяет формат и сравнение вызовов.
- `train_rl.py` → `runs/<run>/{config.json,history.jsonl,summary.json,best/}`, примеры rollouts и validation.
- `export_model.py` → полный HF-чекпоинт. Веса и копии train/val в сдачу не входят.
- Штатный `evaluate.py` → `results/<run>/{metrics.json,predictions.jsonl}`.
- `audit_results.py` сверяет 350 IDs, хэш BFCL, параметры генерации, подкатегории и метрики, выводит парные улучшения и регрессии.
- `make_report.py --font /path/to/Cyrillic.ttf` собирает PDF из проверенных результатов. Для сборки нужны ReportLab и matplotlib.

## Подготовка данных и проверка награды

Сплит по хэшу нормализованного первого запроса строится до нарезки на ходы. Текущий ответ ассистента служит эталоном, предыдущие ответы и результаты инструментов остаются в истории. Инструменты приводятся к формату Qwen; имена с пробелами нормализуются согласованно в схеме и вызовах. Неоднозначные схемы, примеры без инструментов, длинные промпты и дубликаты фильтруются. Текст сразу после ответа инструмента исключён как цель: иначе успешные сценарии с инструментами раздували бы класс no-call.

После фильтров: 10 474 train и 128 validation. В [EDA](evidence/toolace_eda.json) — знаменатели и причины отсева. В [примерах](evidence/toolace_examples.jsonl) — реальные готовые промпты, инструменты, история и ожидаемые вызовы. Все 10 602 эталонных ответа локально проверены с закреплённым шаблоном Qwen и получили строгий балл 1. Это проверка формата и разметки.

Точный набор типизированных вызовов получает 1, порядок свободный, повторы учитываются. Для неточного набора в частичном режиме: 0,9 × сумма баллов лучшего взаимно однозначного сопоставления / max(число предсказанных, число эталонных вызовов). При совпадающем имени балл пары равен 0,25 + 0,75 × доля совпавших аргументов среди объединения ключей. Разные имена дают 0. Пустой, оборванный и сломанный ответ дают 0. При эталоне `[]` непустой ответ без вызова даёт 1; семантика текста отдельно не оценивается.

| Строка ToolACE (с нуля) | Ситуация | Строгая / частичная |
|---|---|---:|
| 0 | `Market_Trends_API(trend_type="MARKET_INDEXES", country="us")` полностью совпадает | 1 / 1 |
| 0 | Та же функция и тип тренда, но `country="ca"`: совпал 1 аргумент из 2 | 0 / 0,5625 |
| 47 | Время в Нью-Йорке, Дубае и Токио; модель дала два верных вызова `Timezones`, Токио пропущен | 0 / 0,60 |
| 46 | Поиск платьев H&M: не хватает локали и размера страницы; ассистент уточнил, без вызова | 1 / 1 |
| 46 | Для того же запроса ассистент начал незакрытый `<tool_call>` | 0 / 0 |

На хосте без Docker запускались два изолированных окружения Python 3.12: обучение с PyTorch 2.8.0+cu126 и оценка с PyTorch 2.11.0+cu129 / vLLM 0.22.0+cu129. TRL 1.16.0, Transformers 5.9.0 и PEFT 0.18.1 закреплены; точные версии каждого прогона есть в `config.json` и `metrics.json`. Для Triton нужны заголовки Python 3.12 (можно извлечь `libpython3.12-dev` локально и передать путь в `CPATH`). На хосте без `nvcc` выставляем `VLLM_USE_FLASHINFER_SAMPLER=0` для **всех** оценок: это отключает сборку sampler при прогреве. Финальная генерация по-прежнему жадная и запускается исходным `evaluate.py`.

## Результаты BFCL

350 задач на модель, одинаковые параметры генерации и тот же оценщик. Все три конфигурации завершили 40 шагов на одной A100; в итог попадает чекпоинт, выбранный по ToolACE.

| Модель | Шаг | Overall | Δ к базе, п.п. | Simple | Multiple | Parallel | Parallel multiple | Irrelevance |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Baseline | — | 69,60% | — | 68,00% | 80,00% | 58,00% | 80,00% | 62,00% |
| RL-1 | 20 | 73,60% | +4,00 | 78,00% | 84,00% | 74,00% | 82,00% | 50,00% |
| RL-2 | 40 | 62,53% | -7,07 | 56,00% | 68,67% | 48,00% | 58,00% | 82,00% |
| RL-3 | 40 | 69,33% | -0,27 | 72,00% | 78,67% | 56,00% | 72,00% | 68,00% |

RL-1 дал лучший Overall: +4,00 п.п. к базе. На тех же примерах исправился 21 ответ, ухудшилось 7. Все регрессии RL-1 относятся к лишним вызовам в no-call задачах. Частичная награда увеличила число шагов с ненулевым градиентом, но RL-2 уступил по Overall. Усреднение по токенам вернуло 6,80 п.п. относительно RL-2; RL-3 остался около базы.
