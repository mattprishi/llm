# HW2 — оптимизация обучения Qwen3 на одной A100 80 GB

> Статус: код и экспериментальный контур подготовлены; численные результаты ниже
> заполняются только фактическими `summary.json` с A100.

## Сетап

- GPU: NVIDIA A100 80 GB, одна GPU.
- Модель: Qwen3, конфигурация из `train.py`, случайная инициализация каждого запуска.
- Токенизатор: `ai-forever/rugpt3small_based_on_gpt2`, зафиксированная revision.
- Данные: `wikimedia/wikipedia`, `20231101.ru`, зафиксированная revision.
- Контекст: 512 токенов.
- Обучение: BF16, TF32, `adamw_torch_fused`, LR `3e-4`, constant-with-warmup,
  seed 42 — одинаково для всех экспериментов.
- Главная метрика: полезные токены в секунду, то есть позиции с `labels != -100`.

Версии библиотек и точное имя GPU записываются в каждом `summary.json`.

## Методика

Baseline и два лучших кандидата обучаются с нуля по 300 секунд. Остальные
конфигурации проходят 75-секундный screening. Первые десять optimizer steps
исключаются из основной throughput-метрики согласно исходному шаблону. Финальная
валидация проводится на одних и тех же 512 примерах после остановки таймера.

Ускорение рассчитывается как:

```text
S = tokens_per_second(final) / tokens_per_second(baseline)
```

## Кольцевые коммуникации

`ring_reduce_scatter` выполняет `world_size - 1` обменов с левым и правым соседом,
накапливая сумму в шарде, соответствующем rank. `ring_all_gather` за такое же число
фаз распространяет готовые шарды по кольцу. `ring_all_reduce` последовательно
вызывает обе операции. Входные тензоры не изменяются.

Проверки в `communications.ipynb` сравнивают все три реализации с PyTorch для
размеров шарда 1, 7 и 31 на двух и четырёх процессах. Обе проверки завершились `OK`.
